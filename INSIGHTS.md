# ВРЕМЕННО — наблюдения для машинного контроля ДС

Живёт до «машинного контроля»: когда правило отсюда стало проверкой (тест, сторож, снимок) или решено, что машина его не
держит, строка уходит отсюда в README («Правила — держит машина» или «Правила словами»), а файл в конце удаляется.
Собрано 25.10 при переезде паттернов в ДС (design#21 → этот PR).

## Что ломалось и почему не поймала машина

| Что | Как нашли | Почему машина не поймала | Кандидат в проверку |
|---|---|---|---|
| Сборки продукта (страница настроек, панель сохранения, мастер, разделы с «Ещё») попали в ДС как компоненты | слово Саши; Carbon держит их в отдельной библиотеке (IBM Products) | реестр проверяет уровень и смысл, но не «основа это или сборка» | нет: граница — решение человека; держит правило словами «ДС — основы, компоненты, правила; сборки — в продукте» |
| Поле в строку и раздел настроек ломались на 768–1100 px рядом с колонкой разделов | ревью глазами | снимки только 390 и 1280 | ширина 1024 в матрице облика (+50 % кадров) или снимок 1024 только у историй с `inline` |
| Ошибка поля в строку стояла под подписью, а красная рамка — справа | ревью | снимки ошибки поля в строку не было; анатомия не знает «ошибка у поля» | анатомия: `FieldNote` — потомок колонки поля (`data-inline` → note внутри правой колонки) |
| Пустое поле с серой «10» выглядело заданным значением (RSMM-55) | Саша жал «Сохранить» и не понимал | placeholder серым — обычный облик, правило не записано | сторож продукта: `placeholder` из одних цифр у числового поля — красный; пример — `helperText` |
| Цель нажатия «?» 16 px на телефоне | ревью | снимки не меряют цели нажатия | тест a11y: у каждой кнопки-значка площадь ≥ 40×40 (axe `target-size` уровня AAA или свой замер в снимке) |
| Раскрытие было вручную в 4 местах, знак у них разный | ревью | правила «одна механика» не было | **сделано**: устройство `expand/own` — класс `ds-expand` только в lib/disclosure.tsx, приманка есть |
| Имена расходились: `busy`, `saving` против `loading`; `selected` против `selectedKey` | ревью | общие имена записаны только словами в react/README | архтест: свойства «идёт действие» — только `loading`, «выбранный ключ» — только `selectedKey` (скан интерфейсов `*Props`) |
| После «Сохранить» фокус улетал в body, читалка молчала | ревью | axe смотрит статичный кадр, не переход | тест поведения: после действия, убравшего кнопку, `document.activeElement` ≠ body |
| Липкая полоса заезжала под панель разделов и полоску телефона, всплывашки закрывали панель | ревью | снимок без панели продукта и без safe-area | снимок истории «полоса над панелью» (`--ds-bottom-inset`) |
| Тестов поведения на новое не было — только список историй | ревью | правило «у каждого компонента истории» есть, «у каждого правила `rule()` тест» — нет | архтест: каждый `rule(` в компоненте упомянут в `__tests__` (по тексту сообщения) |
| Сверка снимков дала 9 «изменённых» кадров у Tabs, ChatThread, ReplyBox, Dialog, которых PR не трогал (28–1332 px, глазом — то же) | сравнение кадров до/после 25.10 | допуск 50 px на кадр ловит шум отрисовки (сглаживание, курсор) | перед записью эталона — второй снимок и сравнение двух снимков между собой; разница между ними — шум, а не облик |
| Главная кнопка формы стояла справа; Carbon — слева на странице | разбор Carbon | правила про выравнивание не было | **сделано** кодом: `ds.css` — в `BottomBar` группа слева, главная правее |
| «?» вместо «i» у справки | разбор Carbon | знак выбирали на вкус | **сделано**: значок `information` в `Toggletip`, «?» в наборе нет |

## Какие правила паттернов проверяемы машиной

Каждый паттерн (`patterns/*.md`) кончается разделом «Чем держится». Сводка:

| Правило | Машина | Чем |
|---|---|---|
| Одна главная кнопка на поверхность | да | `ActionArea` + `rule()` в разработке |
| Опасное не рядом с главной | да | `ActionArea` + `rule()` |
| Одна липкая полоса на страницу | да | `BottomBar` + `rule()` |
| Пустое выглядит пустым | можно | сторож продукта по `placeholder` (кандидат) |
| Справка — дополнительное, не нужное | нет | глаз: нужное пишут подсказкой |
| Пустое состояние: одно действие | частично | `StateView` берёт одно `action`; «по-доброму» — глаз |
| Скелет той же формы | нет | глаз |
| Шаги — от трёх | да | **сделано**: `Steps` + `rule()` на `< 3` (Carbon); DF берёт 4 шага |
| Удаление — подтверждение словом действия | частично | `useConfirm` требует `title`; «не "Да"» — глаз |
| Цвет статуса не один | да | `StatusBadge` рисует знак и слово; контраст — тест |
| Раскрытие ≤ 2 уровней | да | `Card` + `rule()` |
| Паттерн ссылается только на настоящие компоненты | да | тест `patterns.test.ts`: строка «Компоненты:» против экспортов |

## Процесс (не про код)

- Вводная сессии устарела за день: «ДС v0.1, план MIGRATION-REPLAI.md» — на деле v1.2.0, плана уже нет. Сверять факты с
  `origin/main` до работы, а не с брифом.
- Ключ выпуска ДС ушёл вместе с orbit, и никто не заметил до первого выпуска. Кандидат: проверка «выпуск можно сделать»
  при любом переезде инфраструктуры (сухой прогон `release.mjs` в тесте — есть; на живом GitHub — нет).
- Линтер продукта (`scripts/check-design.mjs` в replai) — устаревшая копия правил ДС v0.3. Правила ДС должны жить одной
  копией в пакете (`lint/principles.mjs`), продукт — только вызывать.
- Сторож секретов на ПК не давал читать `release.mjs`: в нём лежал публичный ключ хоста GitHub для ssh выкатки. Ключ ушёл
  вместе с ключом выкатки — но правило «публичный ключ хоста — не секрет» сторож не знает; кандидат — список разрешённых
  форм (`ssh-ed25519 …` в строке known_hosts).
- Шаги «от трёх» подняты в `rule()` (Carbon): продукт с путём из двух шагов станет красным в разработке — это и есть
  способ узнать о расхождении, а не молчать.
